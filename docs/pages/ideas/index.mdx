# Ideas and deferred work

Things worth building that are not being built yet, and the reasoning that got them here.

This is not a backlog of tickets. It exists because the expensive part of a deferred idea is never
the code — it is the context: why it was wanted, what it depends on, what was already discovered
about it, and which decision would need revisiting. That evaporates within weeks, and then the idea
either gets rebuilt from scratch or quietly dropped.

**What belongs here.** Anything deliberately not done, where a future reader would benefit from
knowing why. A feature deferred for priority. A design considered and rejected. A gap found while
building something else. A constraint discovered the hard way.

**What does not.** Work that is actually next — that goes wherever the current plan lives. Bugs
with known fixes; those get fixed. Vague wishes with no reasoning attached.

**Format.** One page per idea. Say what it is, why it is not being done now, what it would touch,
and — most valuable — anything already learned that the next attempt should not have to rediscover.
Date the decision. Delete the page when the thing is built or genuinely abandoned.
