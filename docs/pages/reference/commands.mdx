# Command reference

Run these commands from the monorepo root unless a directory is explicitly shown.

## Setup and development

| Command | Effect |
|---|---|
| `npm run setup` | Runs locked installs in desktop, web, and docs |
| `npm run dev` | Starts all three applications with prefixed logs |
| `npm run dev:desktop` | Starts Tauri and the desktop Vite server |
| `npm run dev:web` | Starts the client-hub Vite server |
| `npm run dev:docs` | Starts Nextra on port 3001 |

## Build and validation

| Command | Effect |
|---|---|
| `npm run build` | Builds desktop frontend, web portal, and docs |
| `npm run build:desktop` | Typechecks and builds the desktop React frontend |
| `npm run build:web` | Builds the web client workspace |
| `npm run build:docs` | Creates the static/production documentation build |
| `npm run check:web` | Typechecks the shared asset library and client app |
| `npm run check:rust` | Runs locked Cargo checking for the Tauri application |
| `npm run check` | Runs version check, frontend/docs checks, and Rust check |

`build:desktop` does not create platform installers — it only runs `tsc && vite build`. For a
distributable bundle, use this from the repo root:

```bash
npm run build:app
```

Do **not** use `npm run tauri build` for anything you intend to distribute. It produces an app with
no LibreOffice, which silently falls back to a host install on the build machine and fails on a clean
one. `build:app` fetches the engines, builds the app, places LibreOffice with `ditto` (preserving the
symlinks and signature Tauri's resource copy destroys), and regenerates the DMG. See
[Third-party engines](/reference/third-party-engines).

## Native engines and edge functions

| Command | Effect |
|---|---|
| `npm run deps:native` | Fetches SHA-256-pinned PDFium and LibreOffice artifacts for this platform and verifies the extracted cache by digest. Run by `npm run setup`; idempotent. ~290MB download, ~800MB on disk. |
| `npm run smoke:functions` | Asserts every Supabase edge function boots; a missing full stack or a 404 fails. Add `--fresh` to recreate the local runtime first — it caches a module on first import and ignores later edits, so a green run after an edit otherwise proves nothing. |

See [Third-party engines](/reference/third-party-engines) and [Testing](/reference/testing).

## R2 maintenance

CDN garbage collection is operator-started; there is no scheduled cron or GitHub Actions job. A
super admin can use web **Admin → CDN GC** or desktop **Settings → CDN garbage collection** for
analyze/confirm/execute/verify. For shell operation,
always create and review a dry-run report before executing:

| Command | Effect |
|---|---|
| `node scripts/gc-cdn-objects.mjs --env staging` | Lists both staging R2 buckets and writes JSON/text reports; deletes nothing. |
| `node scripts/gc-cdn-objects.mjs --env staging --execute` | Rebuilds the report, confirms the asset snapshot, prompts, then batch-deletes staging orphans. |
| `node scripts/gc-cdn-objects.mjs --env production` | Creates the independent production report; deletes nothing. |
| `node scripts/gc-cdn-objects.mjs --env production --execute` | Prompts with totals and a second production confirmation before deleting. |

`--yes` only skips prompts for an explicitly launched `--execute` run. It does not schedule the GC
or bypass the reference and blast-radius rails. See
[CDN garbage collection](/operations/cdn-garbage-collection) for prerequisites, report review,
flags, audit manifests, and recovery from an interrupted run.

## Versioning

| Command | Effect |
|---|---|
| `npm run version:check` | Verifies all manifests, lockfiles, Tauri, Cargo, and changelog |
| `npm run version:patch` | Increments `X.Y.Z` to `X.Y.(Z+1)` everywhere |
| `npm run version:minor` | Increments `X.Y.Z` to `X.(Y+1).0` everywhere |
| `npm run version:major` | Increments `X.Y.Z` to `(X+1).0.0` everywhere |
| `npm run version:set -- X.Y.Z` | Synchronizes an explicit semantic version |

See [Versioning and releases](/reference/versioning) before tagging.
