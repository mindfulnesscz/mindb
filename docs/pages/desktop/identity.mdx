# Stable asset identity

An asset's identity is its **package folder**, not its filename. Every package carries an
eight-character hash suffix (` __a1b2c3d4`) plus a `.dchub.json` manifest mapping filenames to
stable child IDs. The resolved `(stable_id, child_id)` pair is the permanent key for one file.

Resolution order for a child ID: manifest filename match → SHA-256 content match (the file was
renamed) → version lineage (`v1-0-0` → `v1-1-0` of a known asset) → a fresh ID. New child IDs
never reuse an existing manifest identity.

Because identity is decoupled from the name, renaming a file, retitling an asset, or changing
its taxonomy codes all keep the same database row — and with it comments, ratings, approvals,
events and version history. `shortcode` is a display string derived from the filename; nothing
matches on it.

Gallery **parents** are keyed as `__gallery__:<path-under-OUT>`. Renaming a gallery folder
reuses the orphaned parent slot in the same package, so children stay attached while the card's
tags and name update. File children stay rename-proof via content hash / version lineage.

The same resolved pair keys R2 and Supabase. Both planners send every physical file through the
same manifest resolver in the same lexical path order before selecting primaries or gallery-parent
slots. A changed manifest must be persisted before CDN or database work continues; a write failure
aborts instead of leaving an identity that existed only in memory. An asset outside a hashed package
folder has no identity: the CDN steps and the sync both report it and skip it, rather than inventing
a filename-based key.

Assets missing from disk are marked `disconnected`, never deleted — a disconnected row is
reclaimed if the folder reappears.

New packages created through the Vocabulary screen are born with a folder stable ID,
`.dchub.json`, child `c1`, package readme, and a Supabase draft row. The scaffold seeds an
extensionless placeholder in `OUT` reserving `c1`; the first real file with that base name
claims it, so the draft row becomes the published asset instead of a duplicate. If the
deliverable turns out to be a folder of files instead of one file, the gallery parent adopts
that reserved slot.
