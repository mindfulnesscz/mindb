# System troubleshooting

Start by locating the failing boundary: scan, local conversion, local copy, R2, provider OAuth/upload, Supabase sync, or browser/RLS.

- No assets: verify exact `OUT` name, filters, `[99]`, hidden/temp names, and traversal placement.
- Thumbnail errors: **do not install anything.** Rendering is in-process Rust with PDFium and LibreOffice bundled and resolved by absolute path — the old advice to install LibreOffice, Poppler and WebP tools is obsolete, and a host install is deliberately ignored. Read the message instead:
  - `bundled engine '<x>' is missing …` — the engines were never fetched into this checkout. Run `npm run deps:native`. In a packaged app it means a broken build, not a broken machine.
  - `the bundled LibreOffice engine is missing (expected at …)` — since 3.2.2 a release build on macOS/Windows refuses to borrow a host LibreOffice, so this is always a build that was produced by a bare `tauri build` instead of `npm run build:app`. Rebuild; do not install LibreOffice to work around it. Both the packaging script and the release workflow now fail before such a build can be published. See [the mandatory bundled engine](/reference/third-party-engines#on-macos-and-windows-the-bundled-engine-is-mandatory).
  - `… did not finish within 60s and was killed` — since 3.2.2 both subprocesses have a deadline, so a wedged LibreOffice fails one file instead of parking the run. Re-run first: the usual cause is a one-off stuck conversion. If the same document times out repeatedly, it is the document — open it and check for a repair prompt or a linked resource it is waiting on.
  - `Unsupported thumbnail format: <ext>` — not a failure. Only PDF, Office formats and common rasters render; [video is handled by Stream](/cloud-storage/video), not here.
  - A single document failing while others succeed is usually the file: test it by opening it, and see [thumbnail generation](/desktop/thumbnails).
  - On **Linux only**, LibreOffice is a package dependency rather than bundled, so a missing install is real there — see [third-party engines](/reference/third-party-engines#linux-is-a-package-dependency-not-a-bundle).
  - Since 3.2.2 a changed source re-renders on its own (mtime + size are recorded), so deleting an artifact by hand is rarely the fix. Deleting a `thumbnails/` folder is safe but re-renders everything it held; deleting only its hidden `.json` manifests has the same effect.
- Thumbnails correct but very slow in development: check `[profile.dev.package."*"] opt-level = 3` is still in `desktop/src-tauri/Cargo.toml`. Without it a large JPEG takes ~21s instead of ~0.25s. This is a build-profile problem, not a rendering one.
- Portal shows old preview: distinguish local sidecar staleness, R2 inventory shortcut, browser/CDN cache, and stale Supabase URL.
- Asset vanished after rename: determine whether the client was truly migrated and inspect folder suffix/manifest.
- Portal query fails: inspect browser network response, Supabase configuration, generated types, column types, and RLS.
- Downloads fail despite visible card: check status/role helper, singular `download_url`, object existence, URL encoding, and public-domain policy.
- Admin action fails while the header shows you signed in: suspect a [revoked session](/auth#revoked-sessions-a-tab-that-looks-signed-in-but-is-not) before the feature — reads keep working off a token the edge functions already refuse.
- **Window frozen / beachball during rendering, and the run feels serial despite 8-way batching**: fixed in 3.2.2 by declaring the blocking commands `#[tauri::command(async)]` — check the badge to confirm you are not on an older build. If it recurs, a newly added blocking command was declared sync and is running on the main thread.
- **A LibreOffice icon appears in the Dock during a run**: fixed in 3.2.2 by passing the full headless flag set — check the badge first. It was always our own bundled copy, not a host install. Never "fix" a recurrence by editing the nested `LibreOffice.app/Contents/Info.plist`: that breaks the sealed signature notarisation requires. See [headless flags](/reference/third-party-engines#headless-flags-and-why-infoplist-is-not-an-option).
- **Unsure which build or backend you are on**: read the badge — nav rail on the desktop, bottom-left in the portal. It names the environment and version, and colours anything that is not production. See [which build am I looking at](/reference/versioning#which-build-am-i-looking-at). Check this *first* when behaviour disagrees with the code you just changed.
- **`Refusing <x> outside Sotto's approved working directories`**: a native command was handed a path outside the approved roots. Fixed in 3.2.2 for the two causes that made it fire on every asset of a fresh install (a non-recursive picker grant, and persisted roots read only at startup). If it recurs, the path is genuinely outside `$HOME` and `/Volumes` — reassign the folder with **Browse**, and see [filesystem scope](/desktop/native-security#filesystem-scope).
- **`⟳ CDN reconcile — … N failed`**: since 3.2.2 each failure is printed under that line with its stage and reason, and stored in `cdn_move_queue.last_error`. Read those before opening the function logs. The most common is a missing per-project `CF_STREAM_TOKEN` — see [when the reconcile fails](/cloud-storage/access-levels#when-the-reconcile-fails).
- Cloud failures: use [provider troubleshooting](/cloud-storage/troubleshooting).

Preserve the exact section, filename, HTTP status, and response body; generic final counters lose important context.
