# CDN and cloud URLs

| Field | Produced by | Current consumer |
|---|---|---|
| `thumbnail_url` | R2 thumbnail stage | Gallery/detail preview |
| `download_url` | R2 original stage | Primary web **Download** button |
| `download_key` | Pipeline/R2 sync | Stale-object tracking and cleanup |
| `download_urls` | Client-role provider destinations with link generation | Asset detail **Source links** (role-gated) |

## Primary vs source links

- **Download** always prefers the CDN original (`download_url`). Fast, no provider auth in the browser.
- **Source links** are the Dropbox / OneDrive / Google Drive share URLs collected into `download_urls` during cloud export. Entries preferably include `destId` (destination UUID) plus `name`, `provider`, and `url`.

Only destinations with pipeline `role: "client"` write into `download_urls`. Internal-team destinations are omitted on purpose.

## Role gating in the portal

Asset detail loads `clients.cloud_destinations` and shows a source link only when the matching destination is:

- `enabled`
- `showInPortal`
- user’s hub role ≥ destination `minRole`

Entries without a matching destination definition are shown to **staff only**. Configure destinations in the portal Admin drawer — see [Tags and export destinations](/getting-started/tags-and-destinations).

## Reveal in Finder

Separate from download URLs. When a destination has `allowRevealLocal` and the user’s role meets `minRole`, asset detail can send a JSON `POST` to the desktop localhost bridge (`:7624`) with `clientId` + `stableId`. The desktop accepts the production, staging, and local portal origins, resolves the package under its approved `sourceFolder` via an exact parsed `.dchub.json` `stable_id`, and reveals it in the OS file manager. Requires the desktop app running with that client selected.

Database fields control discoverability. For **third-party** share links (Dropbox, Drive, OneDrive) they control nothing else: revoke the provider permission when a link must stop working. R2 objects are no longer in that category — `guest`/`client`/`internal` assets are served through the `cdn-gate` Worker and refuse an unauthorized request ([access levels](/cloud-storage/access-levels)) — but anything ever served on the **public** tier stays fetchable at that URL forever.
