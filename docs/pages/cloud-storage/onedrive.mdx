# Connect OneDrive / SharePoint

## Microsoft Entra setup

1. Register an application in Microsoft Entra ID (this can be the **same** app used for portal OAuth login — see [Authentication](/auth) and the full [Microsoft & SharePoint setup](/cloud-storage/microsoft-setup)).
2. Choose account type deliberately. For a single-tenant organization, copy its Directory (tenant) ID. For multi-tenant/personal access, `common` is supported.
3. Under Authentication enable **Allow public client flows**; the desktop connector uses device authorization and has no client secret.
4. Add delegated Graph permissions `Files.ReadWrite`, `Sites.ReadWrite.All` (SharePoint libraries), `offline_access`, and `User.Read`; grant administrator consent if policy requires it.
5. Enter Application client ID and tenant ID in Sotto, then Connect.

## SharePoint shared library (recommended)

Uploading to a shared SharePoint document library — rather than the connecting user's personal OneDrive — keeps delivery links working across staff changes and uses shared storage. After connecting, paste the **SharePoint site URL** (e.g. `https://contoso.sharepoint.com/sites/Clients`) into the destination and click **Resolve drive**. Sotto resolves the site's default Documents library to a `driveId` and uploads to `/drives/{driveId}/…`. Leave the site URL blank to fall back to the signed-in user's personal drive.

## Background flow

The native Rust backend posts to `/<tenant>/oauth2/v2.0/devicecode`, because Microsoft's endpoint does not allow the Tauri webview origin through CORS. Sotto shows the returned code/verification URL and repeatedly invokes a single native token poll. Success stores access/refresh tokens and expiry; refresh also runs natively.

For each export, files up to 4 MB are PUT to `…/root:/<encoded path>:/content` (simple upload, overwrite). **Larger files use a resumable upload session** (`createUploadSession`) sent in 10 MiB chunks, so large video/design assets no longer hit the simple-upload ceiling. Each chunk is **streamed off disk natively** and never enters the webview — see [How the bytes actually move](/cloud-storage/overview#how-the-bytes-actually-move). When link generation is enabled, Sotto requests an `anonymous` view link and **falls back to `organization` scope** when the tenant blocks anonymous sharing.

A personal (non-business) OneDrive hands back an upload-session URL on a host the app does not reach — `api.onedrive.com` is in neither the CSP nor the native upload allowlist. That has always been true; large uploads to a personal drive are not a supported path, and SharePoint or OneDrive for Business is the intended target.

## Skip-if-unchanged

Before reading anything off disk, Sotto GETs the item already at that remote path and compares its
`size` with the local file's. Only when the sizes match does it compute the local
**QuickXorHash** — Microsoft's own 160-bit content hash, calculated natively and streamed from disk
— and compare it with `file.hashes.quickXorHash`. Both matching means the file is skipped; a
sharing link is still collected for it, so the portal keeps its URL.

**Size alone is never enough**, deliberately: an edit that happens to preserve the byte count would
otherwise leave the client on the old file indefinitely. That is also why the fallbacks all point at
uploading rather than at skipping — a 404, a 401, a Graph outage, or an item that publishes no
QuickXorHash (personal OneDrive publishes SHA-1/SHA-256 instead) all send the file up as before.

Until this existed, OneDrive had no skip at all: every cache miss read the whole file and PUT it, so
a cold `cloud-upload-cache.json` re-sent the entire library. See
[Cloud destination comparison](/cloud-storage/overview#what-a-run-costs-when-its-upload-cache-is-cold).

## Tradeoffs

Device code works well across browsers and lets authorization happen on another device. Overwrite semantics avoid duplicate names. SharePoint targeting removes the dependence on one user's `me/drive`, and upload sessions remove the size limit. Remaining considerations: tenant Conditional Access and sharing policy — if a tenant blocks even organization links, enable sharing for that library in SharePoint admin.

`AADSTS50059` normally means a single-tenant app was called through `common`; enter the tenant GUID. Error 53003 generally indicates Conditional Access/device compliance and requires an Entra administrator.

> After upgrading, **reconnect** the OneDrive destination once so the token is re-issued with the new `Sites.ReadWrite.All` scope.
